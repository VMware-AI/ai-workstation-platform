# AI Workstation Platform — 产品需求规格（节选，用于评测 p20 摘要题）

## 1. 背景

随着大模型在工程场景的渗透加深，许多企业希望在合规可控的前提下让员工使用 AI 编程与文档处理能力。
现有公有云 AI 编程产品（如各家 SaaS 编程助手）在企业环境下存在三个核心障碍：

1. **数据外发风险**：源代码、业务文档、客户资料在调用云端模型时必然出网，与许多企业的合规要求冲突，
   特别是金融、能源、政府、军工、车企等行业。
2. **网络限制**：客户内网默认零出网或强代理，公有云客户端要么连不通要么被层层 MITM
   证书拦截。
3. **品牌中立诉求**：企业 IT 决策层不愿意在生产环境采购"小厂自研 agent"，更倾向于
   已知名字（开源、社区认可）的产品组合，再由集成商交付。

本平台目标是用 VMware 基础设施 + 本地 LLM + 策展开源 agent 解决以上问题，让每个员工
拿到一台预装 AI 工作环境的个人 VM，文件经内网共享，全程不出客户内网。

## 2. 用户角色

| 角色 | 描述 |
|---|---|
| 终端用户 | 公司员工，希望"拖个文件给 AI 帮我改"或"在 VM 里写代码让 AI 重构" |
| 平台管理员 | IT 部门，负责创建/回收 VM、配额、审计、升级 |
| 租户管理员 | 业务部门负责人，管理自己部门的成员（M3 引入） |

## 3. 核心功能

### 3.1 一人一 VM 的 Agent 工作站

- 每位员工通过自助门户申请，管理员审批后自动发一台预装好的 VM
- VM 内预装 2-3 个策展过的 agent（qcoder / Goose / Claude Code），后端统一接本地 LLM 网关
- 用户可选择默认 agent，或在不同任务里切不同 agent
- 系统卷 / 数据卷分离，蓝绿升级时只换系统卷不动数据

### 3.2 共享文件夹 + 双向工作流

- 内网搭建 Samba + ZFS 文件服务，每位员工有 50GB 个人空间
- 员工本机（Windows/macOS/Linux 三端）原生 mount，VM 也 mount 同一目录
- 三个固定子目录：`workspace`（双向）/ `outbox`（用户给 AI 的素材）/ `inbox`（AI 输出落地）
- 误删可从 ZFS 快照 60 秒内恢复

### 3.3 全本地 LLM 推理

- vLLM 部署 Qwen2.5-Coder-32B（默认）/ DeepSeek-Coder-V2-Lite（备选）
- LiteLLM 网关统一 OpenAI / Anthropic 协议，三个 agent 都接它
- Token 用量按 user / agent / model 维度记账，进控制台 Token 看板
- 默认硬约束：VM 禁出公网，所有 LLM 调用必须走内网网关

### 3.4 VCF + NSX 安全隔离

- 每个租户独立 NSX Security Group（vms / pcs / fs / llm 四组）
- DFW 规则：同租户互通，跨租户硬隔离，VM → 0.0.0.0/0 拒绝
- 新增/移除租户通过控制面 API 自动维护 NSX Security Group + 规则
- 全程审计：所有写操作 who/when/what/result 入 audit.db

### 3.5 集中控制面

- Web Console 五视图：圆形图集群总览 / VM 列表 / 用户视图 / Token 用量 / 审计日志
- 自助门户：申请 / 我的 VM / 用量 / 个性化
- 平台管理员可一键升级、一键回滚、批量操作
- 凭据统一 Vaultwarden 管理，源码 / 配置无明文

## 4. 非功能约束

- **air-gap 友好**：全程不依赖 Anthropic / OpenAI 等公网 API
- **OVA ≤ 4GB**：不含 LLM 权重，便于客户内网快速分发
- **首次部署 ≤ 30 分钟**：从执行安装器到第一个用户能用
- **蓝绿升级单用户 ≤ 5 分钟**：home 卷复制不动
- **Token 看板查询 ≤ 1 秒**：1 万条 audit 记录范围内
- **NSX 规则变更 ≤ 30 秒生效**

## 5. 不在 M1 范围内

- Skill marketplace（用户上传 / 同行评审）
- 跨数据中心容灾
- 多模型并行混合调度（Qwen + DeepSeek 同时跑路由）
- 公有云出网代理（保留 M3 按需）
- 多 LLM provider 混合（如某些请求走 Claude API、某些走本地）

## 6. 待澄清的开放问题

- Claude Code 商用 license 在 air-gap 客户场景下能否分发？
- 客户已有的企业网盘（SeaFile / Nextcloud / SharePoint）如何与本平台 fileshare 共存？
- 当客户 GPU 资源不足以承载并发用户时，VM 数应根据什么阈值降级？
- 升级期间用户正在跑长任务的中断策略：强行切 vs 等待登出 vs 通知

## 7. 验收里程碑

- M0（2 周）：摸底 + PoC（文件桥、NSX DFW、agent 评测）
- M1（6 周）：MVP，10 用户内部 demo
- M2（4 周）：1 客户现场试点，50 用户
- M3（持续）：GA，500 用户规模
